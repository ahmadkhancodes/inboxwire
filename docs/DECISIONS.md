## 5 Nov 2026 (M2)
- **mailcore lives in `src/lib/mailcore`** (workspace removed); its 17 tests run from `tests/unit/mailcore.test.ts` in `npm test`.
- **API keys reuse Better Auth org keys** (existing Settings, API keys UI) instead of a separate `api_keys` collection with argon2id; `authEnv()` maps the key's org to an environment (`x-environment` header, default `production`, created on demand). Per-key scopes and a dedicated per-environment key UI come with M4 Keys screen. `/v1/*` is a rewrite to `/api/v1/*`.
- **M2 collections** are behind the Db interface (`src/lib/db/mail-types.ts`, memory + Mongo drivers): environments, oauth_clients, accounts, account_credentials, sync_cursors, connect_links, org_keys. Indexes are in `ensureMailIndexes` (run by `npm run db:indexes`). `account_leases` is deferred to the VPS worker.
- **Envelope encryption**: per-org 32 byte data key wrapped by `MASTER_KEY` (base64, required in production; dev/test derive one from BETTER_AUTH_SECRET). Credentials, tokens and OAuth client secrets are only stored as AES-256-GCM blobs. Owner step: generate `MASTER_KEY` once (`openssl rand -base64 32`) and set it in Vercel before real mailboxes connect; losing it makes stored credentials unreadable.
- **Connect link** stores only the sha256 of the token. Single use is an atomic `consumeConnectLink`; IMAP verifies the login first so a typo (422) does not burn the link. OAuth state (hashed) and PKCE verifier live on the link, are single use, and are bound to the provider. Expired links are kept 7 days (TTL) so the page can say "expired".
- **BYO OAuth only** for Google and Microsoft (no shared client). Pub/Sub topic is optional: without it Gmail runs in polling mode.
- **Hook auth**: Gmail push needs a per-env `?token=` (HMAC-style hash of MASTER_KEY + envId) and, when the client has a push service account, a verified Google OIDC JWT (RS256, issuer, audience = hook URL, service account email). Graph uses `clientState` = the same per-env token and the `validationToken` handshake. Hooks answer 2xx for unknown mailboxes so providers do not retry forever.
- **IMAP send is not wired**: no SMTP library is in the allowed set, so `ImapBackend.send` takes an injected `SmtpSend` and throws `smtp_not_configured` until M3 picks an approach (raw SMTP client written in-repo, or the provider Mailer). Gmail and Graph send work.
- **`poll-imap` cron** polls every account with `mode=polling` (IMAP plus Gmail/Graph without push), claims accounts by pushing `nextPollAt` out 2 minutes, supports sharding and a 45 s budget. Push accounts get their watch renewed in M3 (`watch.expiresAt` is stored, renewal job not built yet).
- Gmail/Graph backends are verified against hand-written fakes, not recorded provider fixtures or a Dovecot container; contract fixtures remain a M3/M5 item.

## 5 Nov 2026 (M3)
- **Scopes live in the Better Auth key's `metadata.scopes`** (`read` < `send` < `admin`; the plugin's `permissions` field is server-only, metadata can be set from the existing Settings UI). A key with no `scopes` (created before M3) keeps full access; a malformed list grants nothing. Needed scopes: read = GET endpoints, send = send, admin = connect links, webhooks, deliveries/replay.
- **Idempotency**: the key is unique per (account, key) for 7 days (`expireAt` TTL). Same key + different canonical body = 422 `idempotency_key_reused`. Requests without a key are never deduplicated. Sends are at-least-once: a crash after the provider accepted but before we record it can duplicate on retry (same as any queue; the lease is 2 minutes).
- **IMAP send uses `nodemailer`'s SMTP transport** (the one allowed dependency, MIT-0). Port 465 = implicit TLS, others require STARTTLS. Accounts connected without SMTP details still fail permanently with `smtp_not_configured` (recorded on the outbox item and as `messageFailed`); no host guessing.
- **Webhook endpoints are per environment** (`envId`) with an allowlist limited to the known event types; the kit's org-wide endpoints (no `envId`) stay and receive every environment's events. Header is `Inboxwire-Signature` (mailcore `sign`); `X-Webhook-Signature` kept for the kit tests and old receivers. `X-Webhook-Id` and the payload `id` are the event id and survive retries and replays. Retry schedule is the kit's (30 s ... 12 h, 8 attempts, about 23 h); mailcore's `nextRetryDelaySec` is not used.
- **Auto-disable**: `failingSince` is set on the first failed attempt and cleared by any success; an attempt at or after 72 h of it disables the endpoint (it is evaluated when a delivery is attempted, so a silent endpoint is only disabled by the next event). Owners are found from Better Auth's `member`/`user` data (`src/lib/auth/owners.ts`). Re-enabling through PATCH clears the clock. Replay of a delivery on a disabled endpoint is a 409.
- **Cursors are signed** (HMAC with MASTER_KEY) and bound to account + folder + query, because Graph's cursor is a URL we call with the mailbox token. Graph additionally refuses non-graph.microsoft.com cursors.
- **Renewal**: `renew-watches` renews anything expiring within 24 h (single lead for Gmail 7 d and Graph about 3 d). Graph renews by PATCH and re-creates on 404, always storing the id so push notifications match. If renewal fails and the watch has expired, the account drops to polling instead of silently missing mail.
- **Routes not built** (not in the task): PATCH/DELETE message, DELETE account, `/v1/usage`, SSE stream. Raw message and attachment bodies are buffered in memory (25 MB cap not enforced yet), true streaming is M4/M5.
- **Docs**: `/docs/api` is a static route that shadows the kit's `api` doc entry (still used for nav and sitemap).


## 5 Nov 2026 (M4)
- **A mailbox is an account row in any environment of the org.** `countMailboxes` (`billing/usage.ts`) is the single number behind the dashboard lamp meter, the plan banner, `GET /v1/usage` and the Stripe quantity. The old `usage` counter for mailboxes/environments is no longer read (seats and events still use it).
- **Plan enforcement.** Developer and Cloud Starter are hard caps: a NEW address past the allowance is refused with 402 `mailbox_limit` before the connect link is consumed (IMAP, OAuth start and OAuth completion); reconnecting an address that already exists is always allowed; mailboxes already connected are never disconnected. Cloud Growth is metered (100 included, extras at `product.extraMailbox`, $0.99): connecting is never refused and `syncExtraMailboxes` sets the quantity of the `inboxwire_extra_mailbox_monthly` line on the subscription (create, update, remove at 0; best effort, a Stripe failure is logged and the next change re-syncs). Self-host is unlimited. `computeEntitlement` now picks the plan line, not `items[0]`, because the extra line sits beside it.
- **Licences.** Issued on `invoice.paid` when the recomputed entitlement is `selfhost` and paid, one per invoice (`invoiceId` unique, so a Stripe retry returns the same key), expiring at the end of the paid period (the verifier adds the 30 day grace and +/-24 h skew from the existing mailcore `check`). Signing key is `LICENCE_SIGNING_KEY` (cloud env only); no key configured means no licence is issued and a warning is logged (the invoice still succeeds, the owner can reissue by replaying the Stripe event). An instance reads `INBOXWIRE_LICENCE` and verifies offline against `LICENCE_PUBLIC_KEY` or `/app/licence-public.pem` (baked in at image build from the `LICENCE_PUBLIC_KEY` repository variable). Valid or grace = Self-host plan in `effectivePlan`; expired or invalid = Developer limits. Grace shows a banner only; it does not make the instance read-only (ARCHITECTURE said "read-only banner": banner done, enforcement deferred). `scripts/verify-licence.mjs` is dependency free and duplicates the 20 lines of check logic on purpose (the image has no tsx); a test runs both against the same keys and times.
- **Deletion.** `DELETE /v1/accounts/{id}` (admin scope) stops the push watch, revokes the token only where a provider supports it (Google revoke endpoint), deletes account, credentials, cursors and outbox rows, and writes a `deletion_record` with `revocation: revoked | not_applicable | failed`. IMAP has a password, and Microsoft Graph has no per-token revoke (revoking sign-in sessions would sign the user out everywhere), so both report `not_applicable`. The record holds only a sha256 of the address, never the address. A failed revoke does not block deletion of our copy. Delivery log rows are not deleted per account (they carry event JSON and expire by TTL, 7 to 90 days by plan); organisation deletion removes them. This is stated in the kit.
- **Purge after cancellation** runs daily (`purge-canceled`, Cloudflare cron list plus a Vercel daily fallback): orgs whose entitlement is `canceled` with the paid period ended 30+ days ago lose their mailboxes through the same deletion flow (reason `post_cancel_purge`). Only mailboxes are purged; the organisation, users and billing record stay so the owner can sign in, export and resubscribe. Idempotent: an org with no mailboxes writes no record. Capped at 200 accounts per run.
- **`/metrics`** needs `Authorization: Bearer $METRICS_TOKEN`; with no token it is closed (404) in production and open elsewhere. It reports totals from the database (mailboxes by state, outbox and delivery counts by status, build, uptime), not per-request counters, because each serverless instance would report a different slice.
- **Live dashboard.** SSE at `/api/app/live` (session auth, org scoped) polls the database every 2 s inside one function and ends after 50 s; `EventSource` reconnects with `Last-Event-ID` (ISO time of the newest event), so no event repeats. State changes therefore show within about 2 s plus the reconnect gap, inside the 5 s target. After three failed connections the browser falls back to polling `/api/app/live/snapshot` every 5 s and says so ("Polling every 5 seconds"). There is no separate event store: the ticker is the webhook delivery log deduped by event id, so an org with no webhook endpoint sees an empty ticker (the empty state says to add one). Line timelines are built from the account row, its deliveries, its outbox and its watch expiry.
- **Dashboard shape.** New top-level pages: Lines, Line detail, Ticker, Deliveries (replay button, uses the same `replayDelivery` as the API), Outbox, Keys and OAuth clients (the existing Settings clients re-exported, scope picker included; the old `/app/settings/...` URLs keep working), Billing (lamp meter: ten lamps, one lamp = 10%, shape and text as well as colour, plus the licence list for self-host). Lamp labels are per state ("sign-in needed" vs "unreachable"), not one "auth error" for two different problems.
- **CASA kit** is built from `src/content/casa-kit.ts` by an in-repo zip writer (`src/lib/zip.ts`, deflate or stored, no library) and served at `/casa/kit.zip` on every plan; CI builds the same zip for each release tag and attaches it (`scripts/build-casa-kit.ts`). The ZAP report cannot be inside a zip built on request, so the kit says it is attached to the GitHub release of the same version; ARCHITECTURE's `/api/casa-kit` path is replaced by `/casa/kit.zip`. The kit claims no certification and lists what stays with the customer.
- **Self-host image.** Next `output: "standalone"` only when `BUILD_STANDALONE=1` (set in the Dockerfile; Vercel builds are untouched). Compose runs `app`, `worker` (`scripts/selfhost-cron.mjs`, plain Node, calls `/api/cron/<job>` and runs `ensure-indexes` once at start so updates need no manual step) and `mongo` (not published). Admin URL = the magic link printed by the console mailer; a separate one-time setup token is not built. The Docker workflow runs on `v*` tags only and has not been run.
- **SDK.** `packages/sdk` is an npm workspace (`@buffersol/inboxwire-sdk`, MIT, zero dependencies). `src/lib/sdk-gen.ts` turns the OpenAPI document into `generated.ts` (types, operation table, a typed `InboxwireClient`); the hand-written client adds auth, environment header, GET retries (sends retry only with an idempotency key) and `verifyWebhook`. A root test fails when the committed `generated.ts` is stale. Publishing needs an npm token (MANUAL_STEPS).
- **OpenAPI fix.** The `Error` component was overwritten by a self-reference (`$ref` to itself); it now carries the real schema. This was found by generating the SDK.
- **No new libraries.** Zip writer, SDK generator, metrics text and SSE are written in-repo (standard library only), so THIRD_PARTY.md has nothing to add.

## 6 Nov 2026 (M5 review)
- **Outbound-target policy.** Customer-supplied hosts (IMAP/SMTP, webhooks) must be public. `src/lib/security/net.ts` blocks the following and checks every DNS answer:
  - loopback, RFC 1918, link-local/metadata, CGNAT, ULA and mapped addresses;
  - single-label names and `.local`/`.internal`/`.lan`.
  - A name that does not resolve is let through, since the dial fails anyway. Reserved test TLDs (`.test`, `.example`, `.invalid`) skip DNS.
  - Self-host opt-out: `ALLOW_PRIVATE_NETWORK_TARGETS=1`.
  - IP pinning against DNS rebinding is deferred (REVIEW P2).
- **IMAP without implicit TLS requires STARTTLS** (`doSTARTTLS: true`), the same rule as SMTP's `requireTLS`. Servers that offer neither cannot be connected. That is intended.
- **Sync is at-least-once for webhooks.** Events are queued (deliveries with `pending` status) before the cursor moves. The sync then delivers within a 20 s budget and the `webhook-retries` cron delivers the rest. A crash between queueing and saving the cursor re-emits the same changes with new event ids.
- **API keys are bound to one environment** through `metadata.environment` (production by default in the UI). A key without it (created before M5) keeps "any environment, chosen by `x-environment`". A bound key with a different `x-environment` gets 403 `environment_not_allowed`. An unknown value binds to nothing.
- **IMAP connect never overwrites a mailbox row of another end user.** It proceeds only if the link's externalId (or, without one, the email) equals the row's externalId; otherwise 409 `mailbox_already_connected`. OAuth reconnects are unaffected, because the provider proves the mailbox.
- **Org deletion revokes first.** `DELETE /api/account` runs `deleteOrgMailboxes` (revoke + delete + `deletion_record`, reason `org_deleted`) before `deleteOrgData`. Deletion records survive the org's data deletion as proof.
- **`/api/health` stays liveness-only.** Mongo health is the `uptime-probe` database target.
- **Indexes self-heal.** `scheduleIndexes` (mongo.ts) runs `ensureIndexes` once per instance in the background after first connect, skipped at build and for memory driver; conflicts (codes 85/86/11000) are logged and skipped, other errors warn and retry next cold start.
