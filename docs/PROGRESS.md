## 5 Nov 2026 (M3): read/search/send API, outbox, webhooks, OpenAPI code done, not deployed
- **Read API `/v1`** (Bearer or x-api-key, `x-environment`): `GET /accounts`, `/accounts/{id}`, `/folders`, `/messages` (cursor + `q` search from:/to:/subject:/after:/before:/has:attachment translated by mailcore per provider), `/messages/{mid}` (`format=json|raw`), `/attachments`, `/attachments/{aid}`, `GET /outbox/{id}`. Cursors are HMAC-signed and bound to account, folder and query (a Graph nextLink is never client-controlled).
- **Send:** `POST /v1/accounts/{id}/messages/send` queues an `outbox` row (new MailStore methods, memory + Mongo, unique (accountId, Idempotency-Key), 7-day TTL, payload encrypted and dropped once terminal), answers 202, sends in `after()`, and the `outbox-send` cron retries (1 m, 5 m, 30 m, 2 h, 5 attempts) and picks up dead workers by lease. Repeat key = same id + `Idempotent-Replayed: true`; same key with another body = 422. Gmail/Graph via their adapters; IMAP accounts via `nodemailer` SMTP (`src/lib/backends/smtp.ts`, threading headers from the parent's Message-ID). Licence in THIRD_PARTY.md.
- **Webhooks:** env-scoped endpoints `/v1/webhooks` (default `messageNew`, allowlist of known events), `Inboxwire-Signature` via mailcore `webhook.sign` (also `X-Webhook-Signature`), delivery log with status code, latency and response snippet (`/v1/deliveries`), one-click replay and bulk replay of failed deliveries (same event id), auto-disable after 72 h of continuous failure with an email to the org owners through the Mailer. The kit's org-wide dashboard endpoints keep working and see every environment.
- **M2 follow-ups:** Gmail watch expiry and Graph subscription id are stored on `account.watch` (watchers return `{id, expiresAt}`); new `renew-watches` cron job (renews anything expiring within 24 h, Graph by PATCH with re-create on 404, failed renewals back off 10 min, an expired watch falls back to polling, auth failures flag the account) in `jobs.ts`, wrangler JOBS and a daily Vercel cron; per-key scopes `read` < `send` < `admin` in Better Auth key `metadata.scopes` (403 `insufficient_scope`), scope picker on Settings, API keys.
- **OpenAPI 3.1** from the Zod schemas (`src/lib/v1/schemas.ts`, `src/lib/openapi.ts`) at `/v1/openapi.json`; docs page `/docs/api` (replaces the old kit stub) renders it, with curl samples, webhook events and a signature verification snippet.
- **Checks:** lint (2 old warnings), typecheck, 159 unit tests (46 new: search translation, pagination/cursors, idempotency, signing, retry, 1 h outage recovery, replay, auto-disable, scopes, renewal, SMTP send, OpenAPI), build all green. No deploy, no e2e run, no screenshots of `/docs/api` yet (do with the deploy). Fixed a flaky hooks test (last base64 char of a signature carries no bits).
